## 3. 교차 점검

- **6.3 ↔ SSR-013/016/010/011**: 순위 1~3은 FAULT/DEGRADED에서도 적용(SSR-013). 순위 4, 5, 7은 SSR-016에 따라 FAULT/DEGRADED에서도 입력이 유효하면 적용. 순위 6(운전자 명령)만 SSR-010/011에 따라 FAULT/DEGRADED에서 미적용. 6.3 주석의 "영향은 순위 6에만 있다"와 일치.
- **6.3 ↔ SSR-015 상태 결정**: OFF 상태에서 순위 3이 첫 주기에만 적용되면 2번째 주기 이후 순위 4(접근위험)가 LOCK을 다시 만든다. A-14는 "OFF = 기능 비활성"이라 하므로 불일치 (R4-02).
- **6.3 순위 4 ↔ SRS-F-007**: 접근위험이 TRUE인 동안 순위 4가 LOCK을 유지하고, F-007은 "6.3의 다른 순위 관계는 바꾸지 않는다"고 명시한다. 따라서 접근위험이 TRUE인 도어에서는 override가 RELEASE를 만들 수 없다. 그런데 F-007 시험과 A-03은 RELEASE를 요구한다 (R4-01).
- **F-017 시험 21쌍 ↔ 상태**: 순위 6이 포함된 쌍은 NORMAL 상태에서만 성립하고, 순위 3이 포함된 쌍은 OFF 상태에서 성립한다. 시험 기준에 이 전제가 없다 (R4-07). 실현 불가 쌍은 없음을 확인함.
- **ASSUMPTIONS ↔ SRS**: A-01(순위 순서), A-03(F-007, F-029, SSR-005), A-04(SSR-008~010, 016), A-09(F-024), A-14(F-016, 6.3), A-15(F-025) 참조는 현재 ID와 일치. A-08은 "SRS 6.5"를 참조하나 현재 절은 6.4다 (R4-06). A-02는 SSR-011, 013, 016과 맞지만 "첫 주기" 문구가 남아 있다 (R4-04).
- **ASSUMPTIONS 편차 표 ↔ TRACE §3**: 두 표의 A-ID 목록 일치(A-01~A-09, A-13~A-16). A-10~A-12는 별도 행. 편차 표에 A-02, A-03, A-04가 있으므로 ISOFIX·자동 잠금 억제 편차(A-02)도 기록에 포함됨. 기록 존재 여부만 확인함 (승인 사실 자체는 결함으로 보지 않음).
- **TRACE ↔ SRS/SSR**: SRS 33건 중 31 + F-028, F-029 모두 §1에 있음. SSR 16건 모두 §1에 있음. OEM-SR 4, FR 7, NFR 2, IF 9 모두 §2에 있음. 그러나 SSR-016의 상위 추적이 OEM-FR-002, OEM-FR-006을 포함하지 않아 두 OEM 요구의 §2 행에도 SSR-016이 없음 (R4-03).
- **수치**: 300 ms(SSR-002), 200 ms(SSR-008), 100 ms(SSR-009), 3 km/h(SRS-L-004), 1,000주기/10 s(SRS-L-005), 100건(SRS-L-006), 0.0~300.0 km/h(SRS-L-007) 모두 OEM 원문과 일치.
- **REQ-03**: SRS에 ASIL 표기 없음 (SRS 본문에 "ASIL" 문자열 없음).

## 5. 확인 사항 (결함 없음)

- SRS F-028, F-029 신설이 6.3과 TRACE §1·§2에 반영됨 (확인).
- SSR 16건이 SRS §2와 TRACE §1에 모두 있음. SSR-015 state 결정과 SSR-014 복귀 규칙이 6.3 주석과 일치함.
- 6.2 열거형: state(OFF, NORMAL, DEGRADED, FAULT). reason_code 17개 전부 사용처가 있음.
- SRS 본문에 ASIL 표기 없음.
- 수치 및 OEM 원문 대조 결과 일치.
- 편차·승인 기록(ASSUMPTIONS 말미와 TRACE §3)의 존재를 확인함. 사용자 승인 사실은 코디네이터 지시에 따라 결함으로 보지 않음.

## 7. 판정 메모

- R4-01은 F-007과 SSR-004가 구조적으로 양립할 수 없는 문제다. 수정 방향(접근위험 LOCK 예외 도입 또는 override 폐기)은 사용자 판단이 필요하다. 예외를 도입하면 OEM-SR-002 수용기준과의 편차를 승인받아야 한다.
- R4-02는 OFF 상태의 지속 규칙이 없다는 문제이며, A-14의 의도("OFF = 기능 비활성")를 SRS에 옮기면 해소된다.
- R4-03과 R4-04는 추적과 편차 기록의 문제이므로 문서 수정만으로 해소된다.
- 재리뷰 시 R3-04, R2-09 부분 조치 항목과 R4-01~R4-08을 표로 확인하고, 6.3·SAFETY-REQ·ASSUMPTIONS·TRACE를 함께 교차 점검한다.
