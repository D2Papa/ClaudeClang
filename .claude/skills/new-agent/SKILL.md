# new-agent

## 절차

1. 사용자에게서 다음을 파악한다. 요청에 이미 있으면 다시 묻지 않는다.
   - 에이전트가 맡을 일 (한 가지 역할에 집중)
   - 코드를 수정해야 하는지, 읽기만 하면 되는지
2. 이름은 kebab-case로 정한다 (예: `api-designer`). `.claude/agents/`에 같은 이름이 있는지 확인한다.
3. 아래 템플릿으로 `.claude/agents/<이름>.md`를 만든다.
4. `CLAUDE.md`의 "서브에이전트" 표에 한 줄을 추가한다.

## 템플릿

```markdown
---
name: <이름>
description: <무엇을 하는 전문가인지>. <언제 사용하는지 — Claude가 자동 위임을 판단하는 근거이므로 구체적으로>.
tools: <필요한 도구만. 읽기 전용이면 Read, Grep, Glob / 수정이 필요하면 Edit, Write 추가 / 명령 실행이 필요하면 Bash>
model: inherit
---

당신은 <역할>입니다.

## 절차
1. ...

## 규칙
- ...

## 보고 형식
- ...
```

## 작성 요령

- `description`이 가장 중요하다. "언제 써야 하는지"가 분명해야 Claude가 알맞게 위임한다.
- `tools`는 최소 권한으로 준다. 생략하면 모든 도구를 물려받는다.
- 서브에이전트는 대화 맥락을 모르므로, 본문에 필요한 절차와 기준을 스스로 완결되게 적는다.
- 결과를 어떤 형식으로 돌려줄지 명시한다. 호출한 쪽은 그 보고만 본다.
