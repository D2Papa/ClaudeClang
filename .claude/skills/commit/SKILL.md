# commit

## 절차

1. 상태 파악: `git status`, `git diff --staged`, `git diff`를 실행한다.
2. 스테이징된 변경이 없으면, 관련 있는 파일만 골라 `git add <파일>`로 스테이징한다.
   - `git add -A`나 `git add .`는 쓰지 않는다.
   - `.env`, 키 파일, `settings.local.json` 등 비밀값이 의심되는 파일은 제외하고 사용자에게 알린다.
3. 서로 무관한 변경이 섞여 있으면 커밋을 나누자고 제안한다.
4. 아래 형식으로 메시지를 작성해 커밋한다.
5. `git log --oneline -1`로 결과를 확인해 보고한다. push는 사용자가 요청할 때만 한다.

## 메시지 형식

```
<type>(<scope>): <요약>

<본문: 무엇을, 왜 바꿨는지 (선택)>
```

| type | 의미 |
|------|------|
| feat | 새 기능 |
| fix | 버그 수정 |
| docs | 문서 |
| refactor | 동작 변화 없는 구조 개선 |
| test | 테스트 추가·수정 |
| chore | 빌드, 설정, 의존성 등 |

- 요약은 50자 안팎, 명령형, 마침표 없이 쓴다.
- scope는 영향받는 모듈·디렉터리 이름이며 생략할 수 있다.
- 본문은 "어떻게"보다 "왜"를 설명한다.
