# requirements-analysis (A-SPICE SWE.1)

## 입력
- 인자(`$ARGUMENTS`): 분석 대상 기능 또는 입력 문서(시스템 요구사항, 고객 요구, 기존 SRS) 경로
- 입력 문서가 없으면 사용자에게 상위 요구(시스템 요구사항 ID)를 확인한다.

## 요구사항 분류

```
요구사항
├── 기능 요구사항 (SRS-F-xxx)        : 시스템이 "무엇을 하는가"
│     └── 기능 안전 요구사항          : 이 문서에서 관리하지 않는다. 별도 안전 문서에서 관리하고,
│                                       필요한 경우 안전 요구사항 ID만 참조(trace)한다.
└── 비기능 요구사항
      ├── 품질 요구사항 (SRS-Q-xxx)   : ISO 25010 품질 특성으로 분류
      ├── 제한 요구사항 (SRS-L-xxx)   : 수치·범위로 표현되는 한계 (자원 사용량, 응답 시간 상한 등)
      └── 제약 요구사항 (SRS-C-xxx)   : 설계·구현에 가해지는 조건 (언어, 표준, 플랫폼, 규격 준수 등)
```

기능 안전 요구사항으로 보이는 항목(ASIL, 안전 목표, 안전 메커니즘 등)을 발견하면 SRS에 쓰지 말고
"안전 문서로 이관 필요" 목록에 모아 사용자에게 알린다.

### ISO 25010 품질 특성 (SRS-Q 분류 기준)
기능 적합성, 성능 효율성, 호환성, 사용성, 신뢰성, 보안성, 유지보수성, 이식성.
각 요구사항에 특성과 하위 특성(예: 신뢰성 > 결함 허용성)을 명시한다. 해당 없는 특성은 "해당 없음 + 사유"를 남긴다.

## 절차

1. 입력 문서를 읽고 요구사항 후보를 도출한다.
2. 후보를 위 분류에 따라 나눈다.
3. 각 요구사항을 아래 속성을 갖춰 작성한다.
4. 품질 기준(아래)으로 자체 점검한다.
5. 추적성 매트릭스를 작성한다.
6. 결과를 `docs/requirements/SRS.md`(없으면 생성)에 저장하고, `review` 스킬로 리뷰를 요청한다.

## 요구사항 작성 형식

| 속성 | 내용 |
|------|------|
| ID | `SRS-F-001` 처럼 영구·고유. 삭제해도 재사용하지 않는다. |
| 제목 | 한 줄 |
| 기술 | "시스템은 ~해야 한다(shall)." 한 문장에 한 가지 요구 |
| 근거 | 왜 필요한가 |
| 검증 방법 | 시험 / 분석 / 검사 / 시연 중 선택, 합격 기준 포함 |
| 우선순위 | 필수 / 권장 / 선택 |
| 상위 추적 | 상위(시스템/고객) 요구사항 ID |
| 하위 추적 | 아키텍처 요소, 상세 설계, 소스, 테스트 ID (후속 단계에서 채움) |
| 상태 | 초안 / 리뷰됨 / 승인됨 |

## 요구사항 품질 기준
- 단일: 한 요구사항에 한 가지만 담는다 ("및", "또는"으로 이어진 복합 요구 분리).
- 검증 가능: 수치와 합격 기준이 있다. "빠르게", "적절히", "충분히" 같은 모호한 표현 금지.
- 일관성: 요구사항끼리 충돌하지 않는다. 충돌 발견 시 사용자에게 보고한다.
- 구현 중립: "무엇"을 쓰고 "어떻게"는 쓰지 않는다 (제약 요구사항 제외).

## 양방향 추적성

- 상향(Upward): 모든 SRS 항목은 상위 요구사항에 연결된다. 연결할 상위가 없으면 "근거 불명" 으로 표시한다.
- 하향(Downward): 모든 SRS 항목은 이후 산출물에 연결된다. 이 스킬 시점에는 빈 칸이며,
  이후 `architecture-design` → `detailed-design` → `implementation` → `unit-test` / `integration-test` 스킬이 채운다.
- 매트릭스는 `docs/traceability/TRACE.md`에 하나의 표로 관리한다.

```
| SRS ID | 상위 요구 | 아키텍처 | 상세 설계 | 소스 | 단위 테스트 | 통합 테스트 |
|--------|-----------|----------|-----------|------|-------------|-------------|
```

추적 누락(고아 요구사항, 요구사항 없는 설계·코드·테스트)은 보고서 끝에 목록으로 제시한다.
