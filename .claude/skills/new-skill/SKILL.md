# new-skill

## 절차

1. 사용자에게서 다음을 파악한다. 요청에 이미 있으면 다시 묻지 않는다.
   - 스킬이 수행할 작업과 결과물
   - Claude가 상황에 맞춰 자동으로 써도 되는지, 사용자가 `/이름`으로만 실행해야 하는지
     (배포·삭제처럼 부작용이 큰 작업은 수동 실행만 허용)
2. 이름은 kebab-case로 정한다. `.claude/skills/`에 같은 이름이 있는지 확인한다.
3. 아래 템플릿으로 `.claude/skills/<이름>/SKILL.md`를 만든다.
   스크립트나 참고 자료가 필요하면 같은 디렉터리에 두고 본문에서 상대 경로로 참조한다.
4. `CLAUDE.md`의 "스킬" 표에 한 줄을 추가한다.

## 템플릿

```markdown
---
name: <이름>
description: <무엇을 하는지>. <언제 사용하는지 — 트리거가 되는 요청 표현을 구체적으로>.
# 수동 실행 전용이면 아래 줄의 주석을 푼다
# disable-model-invocation: true
---

# <이름>

## 입력
- 인자(`$ARGUMENTS`)로 무엇을 받는지

## 절차
1. ...

## 완료 기준
- 무엇을 확인하고 어떻게 보고하는지
```

## 작성 요령

- `description`은 Claude가 스킬을 고르는 유일한 근거다. 사용자가 실제로 쓸 법한 표현을 넣는다.
- 본문은 명령형 단계로 짧게 쓴다. 긴 참고 자료는 별도 파일로 분리한다.
- 스킬은 메인 대화에서 실행되고, 서브에이전트는 별도 맥락에서 실행된다.
  독립적이고 결과만 필요한 작업은 서브에이전트(`new-agent`)가 더 알맞다.
